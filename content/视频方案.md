# 视频号方案 v1（历史设计记录）

> **2026-10-25起请以《每周流程.md》和当期episode数据为准。** 下文保留早期迭代过程，不再作为制作指令。尤其废止“一周/一个月涨46.7%”、未经验证四年/五年分位及固定暴涨开场。现行规范：原文核验 → 按本期数据选题 → 同屏榜单 → 左右104px边距 → 复刻配音、字幕、配乐 → 简洁公众号。

> 每周一条，30–35 秒，固定三段结构。目标是**每周能稳定产出**，不是做爆款。

---

## 一、基本参数

| | |
|---|---|
| 时长 | **30–35 秒（硬上限 35）** |
| 画幅 | 1080 × 1920 竖版 |
| 节奏 | 一屏一个数字，**3 秒一屏** |
| 结构 | 钩子 → 跌了 → 涨了 → 该等 → 收尾 |
| 口播字数 | **≤ 130 字**（约 5 字/秒） |

## 二、画面结构：一屏一张榜

**开场用提问造悬念。** 公式是固定的，内容每周换：

```
口头：你知道有样东西，{周期}涨了 {X} 吗？
画面：只有 {X} 和 {周期}，不出现名字
停顿：1 秒，什么都不说
揭晓：{名字}。
```

公式固定，但**填什么由数据决定**——每周从异动雷达里挑最反常的那一条，不能硬套。如果某周没有足够反常的数据，就退回到"对比开场"（涨最狠 vs 跌最狠），别为了悬念编数字。

**不要一条一屏地切。** 一屏放一整张榜单，所有条目同屏可见；配音念到哪条，白卡片滑到哪条，其余行压暗。

理由：一条一屏的节奏像 PPT 翻页，观众看不到"总量"和"排名"；一张榜停住，观众先扫一眼全貌，再跟着高亮往下走，信息密度高得多。

三张榜，顺序固定：

| 榜 | 条数 | 讲法 |
|---|---|---|
| 跌得最狠 | 3 条 | 一句带过整体，再逐条点名 |
| 涨得最狠 | 4 条 | 同上 |
| 先别碰 | 2 条 | 一句话打包，不用逐条念 |

每张榜配一个标题（跌得最狠 / 涨得最狠 / 先别碰）、一个口径说明（本周 · 农业农村部）、一句画外音式的小注（叶菜整体在跌）。

## 三、节奏

| 时间 | 内容 |
|---|---|
| 0–3s | **提问**：只给数字，不给名字（"+46.7%，什么东西？"） |
| 3–5s | 停顿 1 秒，画面只有数字 |
| 5–9s | **揭晓**：存储设备 → 接入涨榜 |
| 9–14s | 涨榜 → 三条依次高亮 |
| 14–20s | 跌榜 → 三条依次高亮 |
| 20–24s | 先别碰 → 两条依次高亮 |
| 24–28s | 收尾 + 关注引导 |

总长 **25 秒**，上限 30 秒。

收尾卡只做三件事：给一句行动结论、给一个更新承诺、给一个关注按钮。

**不要在结尾贴网址。** 视频号里链接点不开，观众也不会手打一长串英文域名——贴了等于没贴。要引流就把话说清楚："每周日更新，关注不吃亏"。网址只放在公众号文章和主页简介里。

**口径必须标在行上。** 每一行右侧的数值下面标「环比 / 同比 / 本周」——同一张榜里混着不同口径是硬伤，观众会以为 +380% 和 +46.7% 是可比的。口播也要对应说「一个月」「一年」「这周」，不能笼统说「涨了」。

**字幕**：每句配一条烧进画面的字幕（白底圆角胶囊 + 深色字，底部居中）。字幕比口播短，只留关键信息——视频号大量播放是静音的，没有字幕等于没信息。

每条字幕 ≤ 12 字。数字只保留一位小数，口径写在榜头，不念出来。

## 五、生成方式

一条命令出全部素材：

```powershell
python tools/make_video_cards.py
```

产物在 `output/<日期>/视频/`：`card-01.png` … `card-10.png`、`字幕.srt`、以及手写的 `口播稿.md` / `分镜.md`。

图卡模板是固定的，每期**只改脚本顶部的 `EPISODE` 数组**（数字、名称、品类、来源、时长），版式不用动。

再跑一条命令，直接出成片：

```powershell
python tools/make_video.py
```

它会做三件事：把每句话合成配音（Windows 自带语音，离线）、按配音长度分配每张卡的时长、逐帧渲染后编码成 MP4（1080×1920 / 30fps，带缓慢推近、出入画和底部进度条）。

产物：`output/<日期>/视频/今天贵不贵.mp4`，约 2.5 MB，35 秒。

配音是系统自带的合成音，能用但偏机械。如果以后接了云端 TTS（火山引擎），把 `_tts/` 里的 wav 换掉重跑即可，脚本不用改。

## 八、配音

**当前用火山引擎的复刻音色**（`S_Dvf6T9yi2`，自己的声音）。

```powershell
$env:VOLC_KEY = "你的key"
$env:VOLC_TEMPO = "1.25"          # 复刻音色偏慢，用 atempo 变速
python tools/make_voice_volc.py S_Dvf6T9yi2
python tools/make_video_board.py
```

### 关键参数

| | |
|---|---|
| 接口 | `POST /api/v3/tts/unidirectional` |
| `X-Api-Resource-Id` | **`seed-icl-2.0`**（复刻音色）/ `seed-tts-2.0`（内置音色） |
| 认证 | `X-Api-Key`（控制台「API Key 管理」里那个 UUID） |
| 音色 | `S_` 开头的走复刻，其余走内置 |

**踩过的坑**

- `X-Api-Resource-Id` 不是 `volc.service_type.10029`（那是旧值，会一直 `resource not granted`）
- 复刻音色必须用 `seed-icl-2.0`，用 `seed-tts-2.0` 会报 `resource ID is mismatched with speaker related resource`
- 复刻音色对 `speech_rate` 不敏感（实测 20/40/70 时长几乎一样），必须用 ffmpeg `atempo` 控速
- 不同音色原始电平差很多，混音后统一归一化到 0.92 峰值

### 配乐

```powershell
python tools/make_bgm.py        # 火山音频生成，30 秒铺底
python tools/make_video_board.py
```

接口 `POST /api/v3/tts/create`，模型 `seed-audio-1.0`。

**关键坑**：必须显式传 `X-Api-Resource-Id: seed-audio-1.0`。不传的话网关会默认落到
`volc.service_type.10074` 并报 `requested resource not granted`——和语音合成那些 resource id
完全不是一回事。

混音里配乐压在 **0.11 增益（约 -20dB）**，首 0.8 秒淡入、末 1.6 秒淡出，循环铺满全片。

### 备选：edge-tts

不依赖任何 key，微软神经语音，`python tools/make_voice.py`。音色 `zh-CN-YunyangNeural` 等八个中文音色。质量够用，但不是自己的声音。

## 九、不要做的事

- 不做超过 30 秒的版本，宁可少讲一条
- 不写"大家好，今天我们来聊聊"这类开场，第一秒就要有数字
- 不念数据来源（画面角标标就行），念了拖节奏
- 不在一期里讲两个主题，一周只有一个"最反常的数"
- 不做"预测"，只讲已经发生的变化
