# 物价温度 · 生活物价体感面板

一个纯静态的物价感知页面。把分散在统计局、农业农村部、发改委、批发市场、电商和各行业报道里的价格，收拢成"现在什么便宜、什么贵、该不该买"的一张表。

**打开方式**：双击 `index.html`，不需要服务器，无需联网。

## 页面结构

1. **首屏**——一句话定性 + 三列行动清单（现在买划算 / 再忍忍 / 躲不掉），每条一句话理由，点击看详情。
2. **品类索引**——十五个品类的整体位置一览，带色块，点一下筛到该品类。下面的筛选条在滚动越过首屏后**吸顶常驻**，贴在页头下方。
3. **品类分区**——按 01–15 编号，70 条全部摊开，价格平稳的排在每类末尾并视觉降权。
4. **详情弹层**——价格、一年变化、走势图、结论、解释、来源、口径、时点。

视觉是电商内容感：暖橙主色、大圆角卡片、柔和投影、每个条目配图标徽标。容器上限 1880px，卡片是固定卡宽、列数随屏幕自适应（宽屏 6 列 / 1440 下 4 列 / 手机 1 列）。

## 发布

产物就是 `index.html` + `assets/og.png` + `robots.txt`，纯静态，没有构建依赖、没有外链字体和图片，扔到任何静态托管都能跑：

- **GitHub Pages / Cloudflare Pages / Vercel**：把仓库推上去，根目录有 `index.html` 就行，免备案
- **国内对象存储 + CDN**：国内访问更快，但**域名需要 ICP 备案**，这是硬门槛

上线前必须改一处：`og:image` 现在是相对路径 `assets/og.png`，而社交平台抓缩略图要绝对地址。改 `template/index.template.html` 里的 `<meta property="og:image">`，换成 `https://你的域名/assets/og.png`，再重新 build。

也可以顺手改一下 `<title>` 和 `description`，以及 `assets/og.png` 的文案（`tools/make_og.py` 里改）。

`index.html` 是**自包含单文件**：数据内嵌、样式内嵌、无外链字体和图片，离线可用，也可以直接扔到 GitHub Pages / 任意静态托管。

## 更新流程（手动触发）

```powershell
# 1. 改数据
#    data/prices.json —— 改价、改涨跌、改结论、换 meta.asOf、往 changelog 里加一条

# 2. 可选：刷新食品类真实月度序列（需要联网，约 30 秒）
python tools/scrape_food.py

# 3. 合并序列 + 追加当期快照
python tools/seed_history.py

# 4. 重新生成（会先校验，不合格就拒绝生成）
python tools/build.py

# 5. 可选：确认渲染没坏
node tools/smoke.js
```

`build.py` 的校验项：条目字段齐全、`verdict` 和 `quality` 在枚举内、`pct5` 是 0–100 整数、`id` 不重复、每条至少有 `price` 或 `priceText`、数据里不含 `</script>`。校验通过才会写文件，不会产出半成品。

**为什么要跑构建而不是直接改 HTML**：页面里的卡片、榜单、统计数字全是运行时按数据算出来的。手改 HTML 下次构建会被覆盖，而且统计和榜单会跟卡片对不上。

## 条目字段

```json
{
  "id": "pork",                 // 唯一标识，弹层里的"条目编号"
  "name": "猪肉",
  "spec": "白条猪 · 批发",       // 规格口径，说明这个价到底是谁的价
  "unit": "元/公斤",
  "price": 16.22,               // 数字，可空
  "priceText": "1,499 元起",    // 非单值（区间/降幅/指数变化）时用它代替 price
  "mom": -0.3,                  // 环比 %，可 null
  "yoy": -15.6,                 // 同比 %，可 null
  "pct5": 12,                   // 近 5 年位置，0–100
  "verdict": "buy",             // buy | neutral | wait | must
  "reason": "猪价在近五年最低区间，同比少花一成半",  // 结论的一句话理由
  "note": "……",                  // 展开后的解释，写人话，别写数据术语
  "source": "农业农村部 第 40 周（9.28–10.4）",
  "quality": "官方",             // 官方 | 媒体 | 估算
  "asOf": "2026-10-08"          // 这条数据本身的时点，不是页面更新时点
}
```

**展示单位**：`unit` 保持官方口径（如 `元/公斤`），页面展示时自动折成 `元/斤`（×0.5），公斤数用 9px 小字挂在价格旁边备查。已经写成 `元/斤` 的条目原样显示。这样数据可溯源，读者看到的又是自己习惯的单位。
**「比去年贵/便宜多少钱」是自动算的**，不用手工填：只要同时有 `price` 和 `yoy`，页面就用 `price / (1 + yoy/100)` 反推去年同期价，再算差额。所以：

- 填了 `price` + `yoy` → 卡片显示绝对差额（"比去年便宜 3.0 元/公斤"）
- 只有 `priceText`（区间、指数变化）→ 退回显示同比百分比
- 差额小于 0.05 视为持平 → 也退回显示百分比

这条规则决定了**填数时 `price` 要尽量填真实单值**，否则算出来的差额会失真。

`meta.action` 是首屏三列行动清单的策展字段，手工指定哪些条目出现在哪一列、配什么一句话：

```json
"action": {
  "buy":  [{ "id": "pork", "note": "近五年最低价" }],
  "wait": [{ "id": "ddr5", "note": "一年涨了四倍" }],
  "must": [{ "id": "gas92", "note": "年内 +29%，躲不掉" }]
}
```

`meta.headline` 允许内联 HTML（用 `<em>` 标高亮词），`meta.lede` 是纯文本。

`pct5` 是最容易被误读的字段：它是"这个价格在近五年区间里的位置"，用来做体感定位，不是精确统计量。0–20 冰点、20–40 偏低、40–60 中位、60–80 偏高、80–100 高位。

## 三种口径，必须分清

页面把每条数据标成三档，页脚会统计各档数量：

| 口径 | 含义 | 来源举例 |
|---|---|---|
| **官方** | 部委、统计局、地方发改委直接发布 | 农业农村部周报、70 城房价、发改委调价 |
| **媒体** | 财经媒体或行业机构的监测数 | 卓创资讯、中指研究院、证券时报、猫眼 |
| **估算** | 无统一公开口径，基于市场调研的档位判断 | 家电、服装、生活服务 |

**估算条目只用来判断方向和档位，不该拿去当报价。**这是这个站的诚实底线：拿估算冒充官方数据，比不做更糟。

## 四档结论

| verdict | 页面标签 | 用在什么时候 |
|---|---|---|
| `buy` | 现在买划算 | 位置低，且这东西现在买确实划算 |
| `wait` | 再忍忍 | 位置高，或者还在往下掉，不急着买 |
| `neutral` | 价格平稳 | 不贵不便宜，按需买（默认折叠，不占主干版面） |
| `must` | 躲不掉 | 位置高但躲不掉（汽油、理发、高铁） |

注意 `wait` 不等于"贵"。房价是 `wait`，价格位置只有 5，因为它还在阴跌，等一等更划算。

## 走势图怎么来的

每张卡片底部那条折线，来自 `data/history.json`。里面有每个条目的价格点：

```json
"pork": [
  { "d": "2025-10", "v": 19.22, "t": "反推" },
  { "d": "2026-09", "v": 16.27, "t": "反推" },
  { "d": "2026-10", "v": 16.22, "t": "实测" }
]
```

- **反推** = 由当期的 `price / (1 + yoy)` 和 `price / (1 + mom)` 算出来的锚点，不是估的
- **实测** = 当期录入的真实价格，或从农业农村部周报抓来的月度值

**两类曲线，密度不同：**

| 范围 | 点数 | 来源 |
|---|---|---|
| 猪肉、牛肉、羊肉、白条鸡、鸡蛋、蔬菜、水果、草鱼（8 条） | 13 点，逐月 | `scrape_food.py` 抓周报，每月取最后一期 |
| 其余 33 条 | 3 点 | 反推锚点（去年同月 / 上月 / 当前） |

食品那 8 条是真实月度序列，画出来能看出季节性——猪肉春节前冲高、节后断崖、夏天见底，蔬菜冬季贵夏天便宜。其余条目要等 `history.json` 随更新累积。

`seed_history.py` 每次运行会做四件事：合并 `food_series.json`、给新条目补锚点、给已有条目追加当期实测点、已有的历史点一律不动。

**当期月份不会被抓来的值覆盖**——保留 `prices.json` 里手工录入的当期价，避免卡片数字和曲线末端打架。

横轴按真实月份间距摆放（不是按点的序号等距）。**卡片上的「比一年前便宜/贵多少」和曲线用的是同一组首尾点**，所以文字和线不会互相打脸；没有序列的条目才退回 `yoy` 反推。

## 已知边界

1. **生鲜有明显的季节性。**蓝莓、大白菜这类条目，"便宜"只在特定月份成立。`asOf` 和 `note` 里会写清楚当季情况，不要拿 4 月的蓝莓价去理解 10 月的蓝莓。
2. **同一商品的口径差异很大。**猪肉"批发价"和"零售价"能差一倍；鸡蛋产区价和销区批发价也不同。`spec` 字段就是用来防这个坑的。
3. **`pct5` 是估算。**没有五年的逐月序列，位置值是按公开年度区间折算的。它能回答"现在算不算便宜"，不能回答"精确排在第几分位"。
4. **节假日前后的价格会跳。**国庆、春节前后更新时，环比数字参考价值下降，看同比更稳。
5. **曲线密度分两档。**食品 8 条是逐月实测；其余 33 条只有 3 个锚点，点与点之间是直线连接，中间波动看不到，会随更新逐步变密。房价、机票、集采药品这 4 条没有单值价格，不画曲线。
6. **抓来的月度值取「该月最后一期周报」**，不是月度平均。所以它和官方单独发布的"同比/环比"用的周不完全一样，两者相差 1–2 个百分点是正常的。页面统一以曲线首尾点为准，保证文字与图一致。
7. **`mom` 必须是真正的「月环比」。**如果某次调价是一次性的（高铁票价上浮、集采落地、家电成本传导），就不要填进 `mom`，否则曲线会画成"全年平线 + 最后一个月突然跳"。
